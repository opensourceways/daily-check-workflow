# robots.txt 检测方式

## 检测项

| 检测项 | 检测方式 | 预期结果 | 自动化 |
|--------|----------|----------|--------|
| robots.txt 可访问 | HTTP GET robotsUrl（及 robotsAliasUrl） | 200 状态码 | ✅ 脚本 |
| User-agent 存在 | 解析文件内容 | 至少一条 User-agent | ✅ 脚本 |
| allow/disallow 存在 | 解析文件内容 | 二者至少其一出现 | ✅ 脚本 |
| disallow/allow 路径以 `/` 开头 | 解析路径值 | 非空值均以 `/` 开头，违规计入 hardErrors | ✅ 脚本 |
| "引用目录须以 `/` 结尾" | 值是否目录无法自动判定 | 需结合站点路由人工判断 | 👤 人工 |
| 未禁整站 | 分组解析 user-agent 组 | 组内 `Disallow: /` 且无同组 `Allow: /` 抵消即判禁整站（hardError） | ✅ 脚本 |
| sitemap 声明存在 | 解析文件内容 | Sitemap 行存在 | ✅ 脚本 |
| sitemap 链接可访问 | HTTP GET robots 内每条 Sitemap URL | 200 状态码 | ✅ 脚本 |
| Content-Signal 存在且值符合规范 | 解析 + 与 `check-rules.json` 的 `robots.contentSignalExpected` 逐键比对（空格/顺序不敏感） | 规范值 `ai-train=yes, search=yes, ai-input=yes`（2026-10-12 澄清口径） | ✅ 脚本 |
| LLM-Policy 存在且指向 llms.txt 且可访问 | 路径末段匹配 `/llms*` + HTTP GET | 指向可访问的 llms.txt | ✅ 脚本 |
| 主域/alias 域内容一致性 | 分别 GET robotsUrl 与 robotsAliasUrl，逐行比对（忽略空行） | 内容一致；不一致计告警（仅配置了 robotsAliasUrl 的项目） | ✅ 脚本 |
| 主域跨域引用 | Sitemap/LLM-Policy 的 host 与 robots.txt 所在 host 比对 | 不一致计告警（跨主机 Sitemap 声明可能不被搜索引擎识别）；是否整改人工定夺 | ✅ 脚本（判定+告警） |

## 自动化检查

- 检查脚本：`workflow/scripts/check-robots.mjs`（支持 `--site=<id>`，package.json 别名 `check:robots`）
- 执行方式：`node workflow/scripts/run-all.mjs` 或单独执行
- 输出：
  - `workflow/stats/robots-stats.json`，每项目含 `hardErrors`、`warnings`、`verdict`（❌ 硬性错误 / ⚠️ 仅告警 / ✅ 合规），主域与 alias 域分别给出 checks/alias 结果
  - `manual-review/issues/robotstxt/YYYY-MM-DD-robots-规范检查报告.md`：总览表 + 各项目明细（allow/disallow 值、逐条链接访问结果、Content-Signal 取值比对、一致性、原文、结论与建议）
- 口径：sitemap/LLM-Policy 链接可达、Content-Signal 取值、整站封锁、路径起始斜杠、alias 一致性、跨域引用均已由脚本覆盖；规范值调整只改 `workflow/config/check-rules.json`

## 历史人工核查报告

- 2026-10-12 首轮人工规范核查（范围为同时配置 robotsUrl+robotsAliasUrl 的项目）：`manual-review/issues/robotstxt/robots-spec-report-2026-10-12.md`；其后同等检查已全部并入脚本自动生成，人工仅聚焦告警项定夺

## 提 issue 流程（--submit-issues）

- 脚本带 `--submit-issues` 运行时：逐项目先向 AtomGit 目标仓库查重（标题前缀 `[GEO Robots.txt]`，常量定义于 check-robots.mjs，变更会使旧 issue 查重失效），存在未关闭同前缀 issue 则跳过该项目整个"扫描+提单"；查询失败时，有 token 为防重复提单直接跳过，无 token（本地试跑）只扫描不提单
- 触发提单条件：**存在硬性错误**；告警（主域/alias 不一致、跨域引用）仅记入报告供人工定夺，不提单；robotsUrl 未配置的项目不提单
- **单一版正文（robots 维度特例）**：本维度单项目明细很短，不受 issue body 长度限制影响，不做简短/完全双报告拆分，issue 正文直接内嵌完整问题清单、robots.txt 当前内容与规范要点，尾部附当日汇总报告在本仓库的 blob 链接（分支跟随 `GITHUB_REF_NAME`，本地缺省 archive）
- 固定处理说明：修复后关 issue；issue 未关闭期间不会重复扫描/重复提单；误报请评论说明后关闭
- GitHub Action：`.github/workflows/robots-txt-check.yml`（每日 04:00 UTC + workflow_dispatch 支持 `site`/`dry_run`），产物报告 commit 回本仓库 `manual-review/issues/robotstxt/`；cron 仅在默认分支 main 生效，archive 分支合入 main 前用 workflow_dispatch 验证

## 人工检查要点

- disallow/allow 值"引用目录须以 `/` 结尾"的判定（脚本无法识别目录语义）
- UnifiedBus 的 disallow 规则是否误伤正常页面
- MindSpore 文档 / openUBMC 文档 是否需要独立 robots.txt
- 主域跨域引用 alias 域（`*.openatom.cn`）的 Sitemap/LLM-Policy：脚本计告警，是否改同域引用、构建期域名替换脚本是否应覆盖 robots.txt 需人工定夺（呼应 921 复盘）
