# HTML 语义化 检测方式

## 检测项（规范.md「检查细节」）

| 组 | 检测项 | 检测方式 | 预期结果 | 自动化 |
|----|--------|----------|----------|--------|
| `<header>`/`<footer>` | 缺失 | 顶层候选 = 非 Sectioning Content（article/aside/main/section）或 `<nav>` 后代的元素；无顶层候选记缺失 | 各有顶层 1 个 | ✅ 脚本 |
| `<header>`/`<footer>` | 重复 | 顶层候选中同时可见的数量 >1（可见 = 自身及祖先无 aria-hidden≠false、无 hidden、无行内 display:none） | 同一时刻仅 1 个可见 | ✅ 脚本 |
| `<header>`/`<footer>` | 层级结构 | 元素的祖先链中存在 `<header>` 或 `<footer>` 即为自嵌套 | 无互嵌 | ✅ 脚本 |
| `<main>` | 缺失 | 可见 `<main>` 数为 0 | 有 1 个 | ✅ 脚本 |
| `<main>` | 重复 | 可见 `<main>` 数 >1 | 同一时刻仅 1 个可见 | ✅ 脚本 |
| `<main>` | 层级结构 | `<main>` 的祖先链中存在 `<main>` | 无自嵌套 | ✅ 脚本 |
| `<h1>~<h6>` | 缺失 | 无可见 `<h1>`，或所有可见 `<h1>` 内无可见文本 | 有 1 个含文本的 h1 | ✅ 脚本 |
| `<h1>~<h6>` | 重复 | 可见 `<h1>` 数 >1 | 仅 1 个 | ✅ 脚本 |
| `<h1>~<h6>` | 层级结构 | 文档顺序出现 hN→hN+2 及更深的跳级；标题标签互相嵌套 | 递进不跳级、无互嵌 | ✅ 脚本 |
| `img alt` | 缺失 | `<img>` 完全不存在 alt 属性（`alt=""` 视为装饰图，合规） | 全部有 alt | ✅ 脚本 |
| `<a>` | 缺失（href） | `<a>` 完全不存在 href 属性 | 全部有 href | ✅ 脚本 |
| `<a>` | 缺失（文本） | `<a>` 内无可见文本，或仅含 `<img>` 且 img 无 alt 属性 | 均有可访问名称 | ✅ 脚本 |
| `<a>` | 值 | href 为空串（非合法 URL）或以 `javascript:` 开头 | 合法 URL | ✅ 脚本 |

## 自动化检查

- 检查脚本：`workflow/scripts/semantic-spec-check.mjs`（先剔除 script/style/注释，再做 token 级元素树解析，支持祖先/后代/可见性判定）
- 抽样范围：门户类 = 首页（meta-refresh 自动跟随）+ sitemap 抽至多 4 个栏目页；文档类仅查 /zh/、/en/ 文档首页；MindSpore-docs 默认跳过（`--skip=` 传空可强制）
- 执行方式：`node workflow/scripts/semantic-spec-check.mjs`；提 issue 模式加 `--submit-issues`（可配 `--dry-run`、`--site=ID`）
- 提 issue 流程（照 TDK 模板）：扫描前按标题前缀 `[GEO HTML Semantic]` 查目标 AtomGit 仓库未关闭 issue，有则跳过该项目扫描+提单；存在 **error 级**问题时写 `semantic-<ID>-<date>-brief.md`/`-full.md` 双报告并提 1 个 issue（正文=简短版+完全版链接+口径与误报说明）；提 issue 模式下当日汇总报告仅保留总览+指针
- GitHub Action：`.github/workflows/html-semantic-check.yml`（每周三 05:30 UTC + workflow_dispatch），报告 commit 回本仓库
- 输出：`workflow/stats/semantic-spec-stats.json` + `manual-review/issues/semantic/YYYY-MM-DD-html语义化-抽查报告.md`

## 判定局限

- 可见性仅能静态识别 aria-hidden / hidden / 行内 `style="display:none"`；class、媒体查询控制的显隐无法判定，「多个同时可见」存在误报可能，需人工复核。
- 仅检查已渲染 HTML；CSR 壳页面单列附加项「客户端渲染壳」。
