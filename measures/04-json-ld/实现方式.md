# JSON-LD 实现方式

> 本文描述**项目侧如何落地 JSON-LD**（官方 hooks / 生态模块 / 构建产物后处理注入）。例行检查与提 issue 的扫描脚本见 [工具与脚本](工具与脚本.md)。完整规范见 [规范](规范.md)，AI 可执行的落地手册见 [skill/SKILL.md](skill/SKILL.md)。

## 工具选型总览

| 场景 | 工具 | 说明 | 产出 |
|------|------|------|------|
| VitePress | 官方 hooks（`head` + `transformPageData`） | 零依赖、官方机制；站点级挂 `head`，页面级在 hook 中基于 pageData 生成 | 每页 Organization + WebSite + WebPage + BreadcrumbList + TechArticle |
| Nuxt 3/4 | [nuxt-schema-org](https://nuxtseo.com/schema-org)（harlan-zw / Nuxt SEO 套件，v6.x） | Nuxt 生态事实标准；自动注入 WebSite/WebPage 默认节点与 @graph 关联；`@nuxtjs/seo` 用户已内置 | identity（Organization）+ 页面级 define* 节点 |
| Nuxt 类型校验 | [google/schema-dts](https://github.com/google/schema-dts) | Google 官方 schema.org TS 类型 | 编码期类型检查 |
| 构建链受限 | 本措施 skill 脚本 `inject-jsonld.mjs` | 零依赖 Node ≥18，构建完成后扫描 dist HTML 注入 | Organization + WebSite + WebPage + BreadcrumbList（+ 可选 TechArticle） |
| 本地校验 | 本措施 skill 脚本 `validate-jsonld.mjs` | 校验语法/@context/必填属性/嵌套结构/占位符，CI 门禁 | 非零退出码即失败 |
| 富媒体验证 | [Rich Results Test](https://search.google.com/test/rich-results) | Google 官方，校验富媒体资格 | 人工 |
| 词汇验证 | [validator.schema.org](https://validator.schema.org/) | schema.org 官方校验器 | 人工 |

开发落地方式：**优先使用官方 hooks / 生态模块**（数据源在 frontmatter/pageData，随内容自动更新），**兜底使用构建产物后处理注入**，上线前本地校验 + 专项巡检（见 [工具与脚本](工具与脚本.md)）双重把关。

选型原则：**hooks/模块 > 后处理**。后处理只能取 HTML 中已存在的信息（title/description/canonical/mtime），无法获得 frontmatter 级数据（作者、精确发布日期）。

## 方式一：VitePress 项目落地（官方 hooks，零依赖）

完整可复制配置见 [skill/templates/vitepress.config.ts](skill/templates/vitepress.config.ts)。

1. 在 `.vitepress/config.ts` 中声明站点常量（SITE），挂站点级节点：

```ts
import { defineConfig } from 'vitepress'

export default defineConfig({
  lastUpdated: true,
  head: [
    ['script', { type: 'application/ld+json' }, JSON.stringify(organizationNode())],
    ['script', { type: 'application/ld+json' }, JSON.stringify(webSiteNode())],
  ],
})
```

2. 添加 `transformPageData` hook，基于 pageData 生成页面级 `@graph`：

```ts
transformPageData(pageData) {
  if (pageData.relativePath === '404.md') return
  const url = `${SITE.url}/${pageData.relativePath}`.replace(/index\.md$/, '').replace(/\.md$/, '')
  const graph = [webPageNode(pageData, url), breadcrumbNode(pageData, url), articleNode(pageData, url)]
  pageData.frontmatter.head ??= []
  pageData.frontmatter.head.push([
    'script',
    { type: 'application/ld+json' },
    JSON.stringify({ '@context': 'https://schema.org', '@graph': graph }),
  ])
}
```

3. 质量关键——为页面补 frontmatter 数据源：

```markdown
---
title: 安装指南
description: openEuler 24.03 LTS 安装流程。
date: 2026-01-15
image: https://docs.example.com/og-install.png
---
```

`lastUpdated: true` 开启后 git 修改时间自动进入 `pageData.lastUpdated` → `dateModified`。

4. 构建并验证：

```bash
npm run docs:build
node measures/04-json-ld/skill/scripts/validate-jsonld.mjs --dist .vitepress/dist
grep -c 'application/ld+json' .vitepress/dist/index.html   # ≥3（组织/站点/页面图）
```

注意：

- 面包屑中间级默认用路径段命名；站点若有 sidebar title 映射，应替换为映射值（与页面可见面包屑一致）
- 无 frontmatter `date` 时省略 `datePublished`，禁止编造
- 多语言站：按 locale 拆分 SITE 常量（`locales.<locale>` 各自配置）

## 方式二：Nuxt 项目落地（nuxt-schema-org）

1. 安装：`npx nuxi@latest module add schema-org`
2. 配置（完整模板见 [skill/templates/nuxt.config.ts](skill/templates/nuxt.config.ts)）：

```ts
export default defineNuxtConfig({
  site: { url: 'https://www.example.com', name: '站点名称', description: '一句话描述' },
  schemaOrg: {
    identity: { type: 'Organization', name: '组织正式名称', logo: '/logo.png', url: 'https://www.example.com' },
  },
})
```

模块自动输出 WebSite + WebPage 默认节点并挂 @graph 关联；identity 连接 Google Knowledge Graph（Logo/社链出现在搜索结果）。

3. 页面级节点（用法模板见 [skill/templates/nuxt-page.vue](skill/templates/nuxt-page.vue)）：

```vue
<script setup>
useSchemaOrg([
  defineArticle({ title: '安装指南', description: '...', datePublished: '2026-01-15', inLanguage: 'zh-CN' }),
  defineBreadcrumb({
    itemListElement: [
      { name: '首页', item: 'https://www.example.com/' },
      { name: '文档', item: 'https://www.example.com/docs' },
      { name: '安装指南' },
    ],
  }),
])
</script>
```

常用 define* 节点：`defineWebSite` / `defineWebPage` / `defineArticle` / `defineBreadcrumb` / `defineOrganization` / `definePerson` / `defineProduct` / `defineEvent`；未预置类型传 schema.org 原始对象。

注意：

- **模块需要 SSR**；纯 SPA 手动 `useHead({ script: [{ type: 'application/ld+json', innerHTML: JSON.stringify(schema) }] })`
- identity 仅接受 `'Person' | 'Organization' | 'LocalBusiness'`；子类型用 `@type` 数组
- 用 Nuxt DevTools 的 Schema.org 面板实时调试；配合 Nuxt Robots 可自动跳过不可索引路径
- `useSchemaOrg` 默认仅服务端生效（性能考虑），开发模式响应式

## 方式三：skill 兜底脚本（构建产物后处理）

适用：非 VitePress/Nuxt，或无法修改构建配置。零依赖（Node ≥18），位于 [skill/scripts/inject-jsonld.mjs](skill/scripts/inject-jsonld.mjs)。

```bash
# 基础（Organization + WebSite + WebPage + BreadcrumbList）
node measures/04-json-ld/skill/scripts/inject-jsonld.mjs \
  --dist .vitepress/dist \
  --site-url https://docs.example.com \
  --site-name "openEuler 文档" \
  --org-name "openEuler社区" \
  --org-logo https://docs.example.com/logo.png \
  --lang zh-CN

# 文档站（追加 TechArticle；datePublished/dateModified 取文件 mtime，image 用默认图）
node measures/04-json-ld/skill/scripts/inject-jsonld.mjs \
  --dist .vitepress/dist \
  --site-url https://docs.example.com \
  --site-name "openEuler 文档" \
  --org-name "openEuler社区" \
  --org-logo https://docs.example.com/logo.png \
  --lang zh-CN \
  --article \
  --default-image https://docs.example.com/og-default.png
```

行为说明：

- 已含 `application/ld+json` 的页面自动跳过（`--force` 覆盖）；首页只注入 Organization/WebSite/WebPage（无面包屑）
- URL 推导：`index.html → /`、`foo.html → /foo`（`--keep-html-ext` 保留扩展名、`--base-path` 支持子路径部署）
- 取值来源：`<title>`、`<meta name="description">`、`<link rel="canonical">`、文件 mtime——全部真实存在，不编造
- 注入位置：`</head>` 前；JSON 中 `<` 转义为 `\u003c` 防 `</script>` 截断
- 推荐挂 CI：`build && node inject-jsonld.mjs ... && node validate-jsonld.mjs --dist ...`

## 上线验收流程

1. 构建产物 HTML（查看源代码）中存在 `application/ld+json`，且为 SSG/SSR 输出
2. `node skill/scripts/validate-jsonld.mjs --dist <产物目录>` 通过（CI 门禁）
3. `node scripts/checks/check-tdk-jsonld.mjs --dims=jsonld --site=<项目ID>` 通过（sitemap 全量：硬性错误清零；P0 三件套/必填属性等告警项人工定夺；试跑可加 `--max=N`）
4. [Rich Results Test](https://search.google.com/test/rich-results) 抽查核心页面：目标类型零错误
5. [validator.schema.org](https://validator.schema.org/) 抽查：零错误
6. 人工核对取值：与页面可见内容一致，无编造、无占位符
7. 更新 [进展](进展.md) 与 [各项目差异点](各项目差异点.md)
