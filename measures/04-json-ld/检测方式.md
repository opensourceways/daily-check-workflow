# JSON-LD 检测方式

## 检测项

| 检测项 | 检测方式 | 预期结果 | 自动化 |
|--------|----------|----------|--------|
| JSON-LD 存在 | 解析页面 `script[type="application/ld+json"]` | 首页 + 内容页均有（采样验证） | ✅ 脚本 |
| 注入方式 | 检查 SSG/SSR 输出的原始 HTML | 非客户端动态注入 | 🟡 半自动（查看源代码） |
| JSON 语法 | `JSON.parse` | 无语法错误 | ✅ 脚本 |
| @context | 检查块级 `@context` | 固定 `https://schema.org` | ✅ 脚本 |
| P0 三件套覆盖 | 解析 `@type`（含 `@graph` 展开） | Organization / WebSite / BreadcrumbList 在采样页齐全 | ✅ 脚本 |
| 必填属性完整 | 按 Google 各类型必填属性校验 | 齐全且非空 | ✅ 脚本 |
| 嵌套结构 | BreadcrumbList（position+name）/ FAQPage（acceptedAnswer.text）/ headline ≤110 字符 | 无错误 | ✅ 脚本 |
| 占位符 | 递归扫描字符串取值 | 无 TODO/FIXME/待填/占位 | ✅ 脚本 |
| 取值真实 | 对比页面可见内容 | 无编造数据（评分/价格/日期/作者） | ❌ 人工 |
| 富媒体资格 | [Rich Results Test](https://search.google.com/test/rich-results) | 目标类型零错误 | ❌ 人工 |
| 词汇合法性 | [validator.schema.org](https://validator.schema.org/) | 零错误 | ❌ 人工 |
| 本地/CI 门禁 | `skill/scripts/validate-jsonld.mjs --dist <产物>` | 退出码 0 | ✅ skill 脚本 |

## 自动化检查

- 检查脚本：`workflow/scripts/check-jsonld.mjs`
- 采样策略：首页 + `check-rules.json` 的 `samplePages`（`/docs`、`/zh/docs`）+ 各项目 llms.txt 前 2 条真实内容页链接（.md 转 .html），仅统计返回 200 的页面
- 执行方式：`node workflow/scripts/run-all.mjs` 或单独执行
- 输出：`workflow/stats/jsonld-stats.json`（含 `perPage` 每页明细、`requiredMissing` 字段级缺失、`nestedIssues`、`placeholderHits`）

```bash
node workflow/scripts/check-jsonld.mjs                       # 全部项目
node workflow/scripts/check-jsonld.mjs --site=openEuler-portal
node measures/04-json-ld/skill/scripts/validate-jsonld.mjs --dist .vitepress/dist   # 本地 CI 门禁
```

## 人工检查要点

- 查看页面源代码（非 DevTools 元素面板）确认 ld+json 为 SSG/SSR 输出
- AI 生成/脚本生成的取值是否与页面可见内容一致
- 占位符是否在发布前移除
- 面包屑名称是否与页面可见导航一致
- 使用 [Google Rich Results Test](https://search.google.com/test/rich-results) 与 [validator.schema.org](https://validator.schema.org/) 抽查核心页面
