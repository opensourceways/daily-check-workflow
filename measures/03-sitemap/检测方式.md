# Sitemap 检测方式

## 检测项

| 检测项 | 检测方式 | 预期结果 | 自动化 |
|--------|----------|----------|--------|
| sitemap 可访问 | HTTP GET sitemapUrl | 200 状态码 | ✅ 脚本 |
| loc 地址符合规范 | 解析 XML | 每个 `<url>` 的 loc 存在且为以 http/https 开头的完整 URL；缺失/无法解析为硬性错误 | ✅ 脚本 |
| loc 域名合法性 | 与项目合法域名清单比对（domain、domainAlias、sitemapUrl、sitemapAliasUrl 的 host 集合） | loc 主机在清单内；清单外计为告警（921 事故类错误域名）。openEuler 的 `*.openatom.cn` 已通过 domainAlias/sitemapAliasUrl 声明为合法 | ✅ 脚本 |
| loc 能正常访问 | 按全集均匀抽样 8 个 loc HTTP GET | 200 状态码 | ✅ 脚本 |
| lastmod 格式 | 解析 XML | W3C 日期时间格式（YYYY-MM-DD 或含时间/时区）；未来时间为错误 | ✅ 脚本 |
| lastmod 非构建时间 | 启发式：全量条目同值判定 + 与 sitemap 响应头 Last-Modified 同日比对 | 非所有页面相同值；命中时计为告警并注明依据 | ✅ 脚本 |
| lastmod 缺失 | 解析 XML | 可选属性，不做结论性判定；缺失条目全量列入明细 | ✅ 脚本 |
| changefreq 取值 | 解析 XML | 属于 `always/hourly/daily/weekly/monthly/yearly/never` 枚举；非法值为错误，`never` 为告警（仅归档 URL 应使用） | ✅ 脚本 |
| changefreq 缺失 | 解析 XML | 可选属性；缺失条目全量列入明细 | ✅ 脚本 |
| xhtml:link 完整性 | 语言路径规则 + sitemap URL 全集核实（见下） | 仅当页面在全集中**确实存在**其他语言版本时，才要求 `<url>` 内用 `xhtml:link rel="alternate" hreflang href` 列出每个语言版本（包括自身）；单语言页面缺失不计为问题 | ✅ 脚本 |
| sitemap_index 处理 | 识别 index 类型后递归 GET 各子 sitemap | 子 sitemap loc 为绝对 URL 且全部可访问，子项 urlset 汇入项目全集统一分析 | ✅ 脚本 |

## 特殊约定（projects.config.json 字段）

- `newVersions`：配置了该字段的项目，仅检查 index 中路径匹配 `{版本路径}/sitemap.xml` 的子 sitemap（在用新版本，`/` 代表站点根 sitemap），历史版本不在检查范围；index 中缺失对应项时告警。
- `domainAlias` / `sitemapAliasUrl`：其 host 并入合法域名清单，loc 指向这些域名不算问题。
- xhtml:link 语言路径规则（可用 `langMode` 覆盖，默认按项目 id 推断）：
  - `zh-en-prefix`（除 MindSpore 外的项目）：`/zh/xxx ↔ /en/xxx`；无语言前缀页面 ↔ `/zh/...` 与 `/en/...` 两版本。
  - `mindspore`：中文 `/path` ↔ 英文 `/path/en`；文章类页面（news、technology-blogs、activities、version-updates）为 `/type/id` ↔ `/type/en/id`。
  - 核实方式：把项目（含递归子 sitemap）解析到的所有 loc 的路径作为页面全集，按上述规则查找该页面的其他语言版本是否真实存在。

## 自动化检查

- 规范检查脚本：`workflow/scripts/sitemap-spec-check.mjs`（package.json 别名 `check:sitemap-spec`）
- 两种运行模式：
  - 常规检查（默认）：`node workflow/scripts/sitemap-spec-check.mjs [--site=ID] [--skip=Id1,Id2]`，输出含全部明细的汇总报告 + 问题条目明细
  - 提 issue 模式：追加 `--submit-issues`（可加 `--dry-run` 只打印正文不提单），按项目查重→扫描→双报告→提单，汇总报告仅保留总览
- 默认跳过 `MindSpore-docs`（其 sitemapUrl 当前 404，真实地址待修正）；`--skip=` 传空可强制全查
- 输出（均写入报告归档目录 `scheduled-reports/sitemap/<YYYY-MM-DD>/`，目录内文件名不含日期）：
  - 常规模式：`report.md`（总览 + 各项目明细）、`detail.md`（缺失/不符合条目完整清单，单类超上限截断并注明总数：硬性错误 3000、缺失类 2000、域名不一致 1000）
  - 提 issue 模式：同名汇总报告（简版）+ 每问题项目 `<项目ID>-brief.md` / `<项目ID>-full.md`（当日目录内）
  - 机器可读：`workflow/stats/sitemap-spec-stats.json`（两种模式都输出）
- 旧版轻量快速检查：`workflow/scripts/check-sitemap.mjs`（支持 `--site=<id>`，输出 `workflow/stats/sitemap-stats.json`），结果口径较粗，规范判定以 `sitemap-spec-check.mjs` 为准

## 自动提 issue 流程

1. 按项目查重：在该项目 AtomGit 仓库（owner/repo 由 `projects.config.json` 的 gitcode `repo` URL 解析）查标题前缀 `[GEO Sitemap]` 的未关闭 issue；存在则跳过该项目整个"扫描+提单"（issue 未关闭期间不重复扫描、不重复提单）。查重失败时：有 token 跳过扫描（宁漏勿重），无 token（本地）仅扫描不提单。
2. 扫描后触发条件：存在硬性错误或告警（sitemap 不可访问、loc 缺失/非绝对/非法域名、lastmod 格式/未来时间/疑似构建时间、changefreq 非法值/never、index 子项异常、xhtml:link 全集核实缺失、loc 抽样不可访问等）；仅可选属性缺失不触发。
3. 提 1 个 issue 到该项目仓库：标题 `[GEO Sitemap] <项目名>（<ID>）：sitemap 属性规范问题（错误 N 类 / 告警 M 类）`；正文 = 简短版内容 + 指向本仓库完全版报告的链接（`https://github.com/opensourceways/daily-check-workflow/blob/<分支>/scheduled-reports/sitemap/YYYY-MM-DD/...-full.md`，分支取 `GITHUB_REF_NAME`，本地缺省 `archive`）+ 固定处理说明。
4. GitHub Action：`.github/workflows/sitemap-spec-check.yml`，每日 04:30 UTC（北京时间 12:30）定时 + `workflow_dispatch` 手动（inputs：`site`、`dry_run`），带 `ATOMGIT_TOKEN` secret 运行 `--submit-issues`，产物 commit 回本仓库 `scheduled-reports/sitemap/<YYYY-MM-DD>/`。注意：cron 只在默认分支（main）生效，archive 分支合入 main 前用 workflow_dispatch 验证。
5. 前缀 `[GEO Sitemap]` 是查重依据，变更会使旧 issue 查重失效造成重复提单。

## 人工检查要点

- 站点实际存在但未收录进 sitemap 的语言版本，全集核实法无法发现，需人工确认语言覆盖
- `newVersions` 版本列表是否随新版本发布及时更新（921 事故规避）
- 多个 Vitepress 项目间 sitemap index 生成逻辑是否同步
- lastmod 构建时间判定为启发式，最终以各项目生成逻辑为准（见 各项目差异点.md 实现方式表）
