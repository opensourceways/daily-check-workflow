# llms.txt 实现方式

> 本文描述**项目侧如何落地 llms.txt**（生态插件 / 兜底脚本）。例行检查与提 issue 的扫描脚本见 [工具与脚本](工具与脚本.md)。完整规范见 [规范](规范.md)，AI 可执行的落地手册见 [skill/SKILL.md](skill/SKILL.md)。

## 工具选型总览

| 场景 | 工具 | 说明 | 产出 |
|------|------|------|------|
| VitePress | [vitepress-plugin-llms](https://github.com/okineadev/vitepress-plugin-llms) | Vite / Vue.js / Vitest / Rolldown 官网同款，遵循 llmstxt.org v2，零配置 | `llms.txt` + `llms-full.txt` + 每页 `.md` |
| Nuxt 3/4 | [nuxt-llms](https://github.com/nuxtlabs/nuxt-llms) | NuxtLabs 官方模块（atinux / farnabaz 维护） | `/llms.txt`（默认）+ `/llms-full.txt`（需启用 `full`），自动预渲染 |
| Nuxt Content ≥3.2 | `@nuxt/content` 内置集成 | 与 nuxt-llms 配合，自动收录 `content/` 全部内容 | 同上 |
| 无法引入构建依赖 | 本措施 skill 脚本 `generate-llms-txt.mjs` | 零依赖 Node ≥18，从 sitemap 或构建产物生成 | `llms.txt`（+ 可选 `llms-full.txt`） |
| 部署后校验 | [llms-txt-check](https://github.com/portdeveloper/llms-txt-check) | 校验部署产物：文件可达性 + 全部链接有效性 | 非零退出码即失败，可挂 CI |

开发落地方式：**优先接入生态插件**（构建时自动生成、零维护、输出真 Markdown），**兜底使用本措施 skill 脚本**，上线后用巡检脚本（见 [工具与脚本](工具与脚本.md)）持续验证。

选型原则：**生态插件 > 兜底脚本**。插件随每次构建自动更新；兜底脚本的 HTML 提取为近似文本，仅在构建链受限时使用。

## 方式一：VitePress 项目落地

### 步骤

1. 安装插件：

```bash
npm install vitepress-plugin-llms --save-dev
```

2. 在 `.vitepress/config.ts` 接入（完整模板见 [skill/templates/vitepress.config.ts](skill/templates/vitepress.config.ts)）：

```ts
import { defineConfig } from 'vitepress'
import llmstxt from 'vitepress-plugin-llms'

export default defineConfig({
  vite: {
    plugins: [llmstxt()],
  },
})
```

3. **质量关键**——为收录页面补 frontmatter `description`（生成链接描述的唯一来源）：

```markdown
---
title: 安装指南
description: openEuler 22.03 LTS SP4 物理机与虚拟机安装流程。
---
```

4. 可选内容裁剪：`<llm-only>仅 AI 可见</llm-only>`、`<llm-exclude>仅人类可见</llm-exclude>`
5. 构建并验证产物：

```bash
npm run docs:build
ls .vitepress/dist/llms.txt .vitepress/dist/llms-full.txt
```

构建产物结构：

```
.vitepress/dist/
├── llms.txt                 # 结构化索引
├── llms-full.txt            # 全量单文件
├── install.html             # 人类版
└── install.md               # 每页 Markdown 版
```

6. 部署后验证：

```bash
npx llms-txt-check https://docs.example.com
```

### 多语言决策

插件作者建议多语言文档仓库"仅收录英文"，适用于英文技术社区。**本专项决策：中文站点保持中文**——站点内容与受众均为中文，机器翻译引入信息损失，且现代模型（含国内模型）中文能力成熟。中文站不要因该插件提示而删除中文内容。

## 方式二：Nuxt 项目落地

### B1：Nuxt + Nuxt Content（≥3.2）

```bash
npm i nuxt-llms
```

```ts
export default defineNuxtConfig({
  modules: ['nuxt-llms', '@nuxt/content'],
  llms: {
    domain: 'https://www.example.com',   // 必填
    title: '站点名称',
    description: '一句话描述',
    full: {                               // 启用 /llms-full.txt（默认关闭）
      title: '站点名称 — Full Documentation',
      description: '全部内容的单文件版本',
    },
  },
})
```

`@nuxt/content` 通过 nuxt-llms 的 hooks 自动把 `content/` 目录全部内容收录进两个文件，无需逐页配置。完整模板见 [skill/templates/nuxt.config.ts](skill/templates/nuxt.config.ts)。

### B2：纯 Nuxt（无 Nuxt Content）

```ts
export default defineNuxtConfig({
  modules: ['nuxt-llms'],
  llms: {
    domain: 'https://www.example.com',
    title: '站点名称',
    description: '一句话描述',
    sections: [
      {
        title: 'Docs',
        description: '产品文档',
        links: [
          { title: '快速开始', description: '五分钟上手', href: 'https://www.example.com/docs/quick-start' },
          { title: 'API 参考', description: '全部接口说明', href: 'https://www.example.com/docs/api' },
        ],
      },
    ],
    notes: '备注信息（固定出现在文件末尾）',
  },
})
```

### 配置字段说明（nuxt-llms）

| 字段 | 必选 | 含义 |
|------|------|------|
| `llms.domain` | 是 | 站点域名（含协议），链接绝对 URL 的前缀 |
| `llms.title` | 否 | H1 站点名称 |
| `llms.description` | 否 | blockquote 摘要 |
| `llms.sections[].title` | 是 | H2 分节名 |
| `llms.sections[].links[].title` / `href` | 是 | 链接标题与绝对地址 |
| `llms.sections[].links[].description` | 否 | 链接描述 |
| `llms.notes` | 否 | 固定出现在文件末尾的备注节 |
| `llms.full.title` / `description` | — | 设置后启用 `/llms-full.txt` 路由 |

### 动态扩展（从 CMS/API 收录）

```ts
// server/plugins/llms.ts
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('llms:generate', (event, options) => {
    options.sections.push({
      title: 'API Documentation',
      description: 'REST API endpoints',
      links: [{ title: 'Authentication', description: '鉴权方式', href: 'https://www.example.com/api/auth' }],
    })
  })
})
```

可用 hooks：`llms:generate`（每次请求 `/llms.txt` 时修改结构化数据）、`llms:generate:llms-full`（追加 llms-full.txt 内容块）。

> Nuxt 路径注意：nuxt-llms 生成**服务端路由**并自动预渲染，不要在 `public/` 手工放文件；确认 `nitro.prerender` 未排除这两个路由。

## 方式三：skill 兜底脚本

适用：非 VitePress/Nuxt 项目，或构建链不允许新增依赖。脚本位于 [skill/scripts/generate-llms-txt.mjs](skill/scripts/generate-llms-txt.mjs)，零依赖（Node ≥18）。

```bash
# VitePress / Nuxt 构建产物 → 生成到产物目录（随部署直接上线）
node measures/02-llms-txt/skill/scripts/generate-llms-txt.mjs \
  --source dist --dist .vitepress/dist \
  --domain https://docs.example.com \
  --title "openEuler 文档" \
  --description "openEuler 官方文档站" \
  --full

# 从线上 sitemap 引导生成（无构建产物时）
node measures/02-llms-txt/skill/scripts/generate-llms-txt.mjs \
  --source sitemap --sitemap https://www.example.com/sitemap.xml \
  --domain https://www.example.com \
  --title "站点名称" --description "一句话描述" \
  --out ./public --full
```

行为说明：

- `llms.txt`：生成 H1 / Summary / Info / Pages / Optional 完整结构；页面标题取 `<title>`，描述取 `<meta name="description">`（300 字符截断）；URL 默认去 `.html`（可用 `--keep-html-ext` 保留）
- `llms-full.txt`（`--full`）：dist 模式优先拼接页面 `.md` / `.html.md`（真 Markdown），否则 HTML 正文近似提取（去导航/脚本/样式，保留正文与标题层级）
- 超 100,000 字符输出告警（对应规范拆分索引策略）；`--max-pages`（默认 500）限制 full 收录页数
- 建议挂 CI：`build && node generate-llms-txt.mjs ...`，保证随构建刷新

## Skill 落地包

[skill/](skill/) 目录为自包含技能包，可直接复制到任意项目使用，或作为 AI agent 的操作手册：

| 文件 | 用途 |
|------|------|
| [skill/SKILL.md](skill/SKILL.md) | 技能入口：前置信息收集 → 技术栈决策树（VitePress / Nuxt / 兜底）→ 验收清单 → 禁止事项 |
| [skill/scripts/generate-llms-txt.mjs](skill/scripts/generate-llms-txt.mjs) | 兜底生成脚本（零依赖） |
| [skill/templates/llms.txt.template](skill/templates/llms.txt.template) | llms.txt 手写模板（含逐字段注释） |
| [skill/templates/vitepress.config.ts](skill/templates/vitepress.config.ts) | VitePress 配置片段 |
| [skill/templates/nuxt.config.ts](skill/templates/nuxt.config.ts) | Nuxt 配置片段 |

使用方式：

- **人工落地**：按 SKILL.md 决策树选择路径，照步骤执行，对照验收清单勾验
- **AI 落地**：将 skill/ 目录提供给 agent（或指向 SKILL.md），agent 按手册自动完成安装、配置、生成与验证

## 上线验收流程

1. 构建产物包含 `llms.txt`（及启用后的 `llms-full.txt`），随部署发布到站点根路径
2. `npx llms-txt-check https://<域名>` 退出码为 0（部署层重定向/域名迁移常常破坏可达性，此项必做）
3. `node scripts/checks/check-llms-txt.mjs --site=<项目ID>` 通过（P0 硬性错误清零；告警项人工定夺）
4. robots.txt 已配置 `LLM-Policy: /llms.txt`（01 措施联动）
5. 人工验收：只把 llms.txt 提供给 AI 助手，确认能正确回答站点核心问题（官方推荐做法）
6. 更新 [进展](进展.md) 与 [各项目差异点](各项目差异点.md)
