# llms.txt 检测方式

## 检测项

| 检测项 | 检测方式 | 预期结果 | 自动化 |
|--------|----------|----------|--------|
| /llms.txt 可访问 | HTTP GET /llms.txt | 200 状态码 | ✅ 脚本 |
| Content-Type | 检查响应头 | `text/plain` 或 `text/markdown`（charset=utf-8） | ✅ 脚本 |
| Title 存在且唯一 | 解析 Markdown H1 行 | 恰好一行 H1，且为第一行 | ✅ 脚本 |
| Summary 存在 | 解析 Markdown blockquote 行 | 至少一段引用摘要 | ✅ 脚本 |
| 链接结构 | 解析 `- [标题](URL): 描述` 列表 | ≥1 个 H2 分节；链接为绝对 URL（推荐）或根相对路径，全部可解析 | ✅ 脚本 |
| 链接描述覆盖率 | 统计带描述链接占比 | ≥80%（P1 基线）；同时检出空冒号、无标题、超 300 字符描述 | ✅ 脚本 |
| 单节链接数 | 按 H2 分节统计链接分布 | 每节 5–20 条（推荐值，超限列出分节名） | ✅ 脚本（informational） |
| 单文件体积 | 统计字符数 | ≤100,000 字符，超限触发 `/_llms/` 拆分策略 | ✅ 脚本 |
| llms-full.txt 可访问 | HTTP GET /llms-full.txt | 200（P1 基线） | ✅ 脚本 |
| llms-full.txt 真实体积 | Range 请求（`bytes=0-0`）解析 Content-Range | 不设上限，记录体量供裁剪决策 | ✅ 脚本 |
| llms-full.txt 文件头 | 首个 `---` 分隔线前解析 H1 + Summary | 存在且与 llms.txt 的 H1 一致 | ✅ 脚本（截取前 2MB 分析） |
| llms-full.txt Source 格式 | 识别 `Source:` 行 / 裸 URL 行 / `url:` YAML / `> URL:` blockquote | 每页含 `Source: <绝对URL>` 独立成行 | ✅ 脚本（格式分类） |
| HTTP 发现头 | 检查 `Link: rel="describedby"` / `X-Llms-Txt` 响应头 | 均返回（P1/P2，可在托管层配置） | ✅ 脚本 |
| robots.txt LLM-Policy | 检查 robots.txt | 包含指向 llms.txt 的声明 | ✅ 脚本（计告警，提单归 01-robots-txt 维度） |
| 抽样链接可达 | 抽取前 3 条链接逐个 GET | 全部 200 | ✅ 脚本 |
| .well-known 别名 | GET /.well-known/llms.txt | 200 且 Content-Type 为 text/plain（P2）；**200 但返回 HTML 判定为伪别名**（SPA 兜底路由，比 404 更易误导） | ✅ 脚本 |
| 部署产物完整性 | `npx llms-txt-check <域名>` | 退出码 0（CI 门禁） | ✅ 外部工具 |
| 内容准确性 | 只提供 llms.txt 给 agent，测试能否回答站点核心问题 | 正确回答"是什么/怎么装/怎么用" | ❌ 人工 |
| 分组与链接合理性 | 人工审阅分节组织、重要性排序 | 分组合理、描述准确、随站点更新维护 | ❌ 人工 |

## 自动化检查

- 检查脚本：`scripts/checks/check-llms-txt.mjs`（package.json 别名 `check:llms`，参数与执行流程见 [工具与脚本](工具与脚本.md)）
- 两种运行模式：
  - 常规检查（默认）：`node scripts/checks/check-llms-txt.mjs [--site=ID]`，含全部明细的汇总报告
  - 提 issue 模式：追加 `--submit-issues`（可加 `--dry-run` 只打印正文不提单），按项目查重→扫描→brief/full 双报告→提单，汇总报告仅保留总览
- 执行方式：GitHub Actions 每日定时（见下文）或 `node scripts/checks/run-all.mjs` / 单独执行
- 输出（均写入报告归档目录 `scheduled-reports/llms/<YYYY-MM-DD>/`，目录内文件名不含日期）：
  - `report.md`（总览表 + 各项目明细；提单模式仅总览 + full 指针清单）
  - 提单模式对发现 P0 硬性错误的项目：`<项目ID>-brief.md` / `<项目ID>-full.md`
  - 机器可读：`scripts/stats/llms-txt-stats.json`（两种模式都输出）
    - 基础：可访问性/CT/H1/Summary/链接数/URL 形式/体积
    - 描述：`descCoverage`（覆盖率）、`descCoverageOk`（≥80%）、`linksEmptyColon`/`linksUntitled`/`descOver300Count`
    - 分节：`sectionLinkDist`（每节链接数）、`sectionsOverLimit`（超 20 条的分节）
    - llms-full：`llmsFullTotalBytes`（Range 实测真值）、`llmsFull.headOk`/`headMatchesLlms`/`sourceFormat`（source-line / bare-url / url-yaml / url-blockquote / none）
    - 发现机制：`linkHeader`/`xLlmsTxtHeader`、`wellKnownOk`（含 `wellKnownBrokenAlias` 伪别名识别）
    - 联动：`robotsLlmPolicyPresent`、抽样链接可达明细
    - 分级：`hardErrors`（P0）、`warnings`（P1/质量项）、`verdict`（❌/⚠️/✅）

## 提 issue 流程（--submit-issues）

- 逐项目先向 AtomGit 目标仓库查重（标题前缀 `[GEO llms.txt]`，常量定义于 check-llms-txt.mjs，变更会使旧 issue 查重失效），存在未关闭同前缀 issue 则跳过该项目整个"扫描+提单"；查询失败时，有 token 为防重复提单直接跳过，无 token（本地试跑）只扫描不提单
- 触发提单条件：**存在 P0 级硬性错误**（验收基线 P0 各行 + 100k 体积）；P1/质量告警仅记入报告供人工定夺，不提单；llmsUrl 未配置的项目记 ❌ 但不查重、不提单
- 特殊口径：robots LLM-Policy 联动缺失在本维度**只计告警**——同一根因的提单由 01-robots-txt 维度（前缀 `[GEO Robots.txt]`）负责，避免跨维度重复提单
- 报告形态：双报告（`<ID>-brief.md` 简短版进 issue 正文 + `<ID>-full.md` 完全版挂链），与 TDK 重复/Sitemap/HTML 语义化维度一致
- 固定处理说明：修复后关 issue；issue 未关闭期间不会重复扫描/重复提单；误报请评论说明后关闭
- GitHub Action：`.github/workflows/llms-txt-check.yml`（每日 05:00 UTC + workflow_dispatch 支持 `site`/`dry_run`），产物报告 commit 回本仓库 `scheduled-reports/llms/<YYYY-MM-DD>/`；cron 仅在默认分支 main 生效

## 人工检查要点

- llms.txt 内容是否准确反映站点核心信息（Title/Summary/分节）
- 链接描述是否来自页面 frontmatter description（禁止编造）
- 是否混入 noindex/hidden/404 页面
- 中文站点是否保持中文（禁止机器翻译）
- llms-full.txt 每页是否含 标题 + Source URL + 完整正文
