# TDK 检测方式

## 检测项

| 检测项 | 检测方式 | 预期结果 | 自动化 |
|--------|----------|----------|--------|
| title 存在 | 解析 `<title>` 标签 | 每页有 title | ✅ 脚本 |
| title 唯一性 | 对比多页面 title | 无重复 | ✅ 脚本 |
| title 格式 | 解析内容 | 遵循"页面内容 - 网站名称"模式 | 🟡 半自动 |
| description 存在 | 解析 `<meta name="description">` | 每页有 description | ✅ 脚本 |
| description 唯一性 | 对比多页面 | 无重复 | ✅ 脚本 |
| keywords 存在 | 解析 `<meta name="keywords">` | 每页有 keywords（优先级低） | ✅ 脚本 |

## 自动化检查

- 检查脚本：`scripts/checks/check-tdk.mjs`
- 执行方式：`node scripts/checks/run-all.mjs` 或单独执行
- 输出：`scripts/stats/tdk-stats.json`
- TDK 重复检查：`scripts/checks/check-tdk-duplicate.mjs`（`pnpm run check:tdk-dup`）——按 sitemap 全量页面逐页请求 HTML 后分组判重（title/description/keywords），报告输出到 `scheduled-reports/tdk/<YYYY-MM-DD>/`，完整数据见 `scripts/stats/tdk-duplicate-stats.json`；默认跳过 openEuler-docs、openGauss-docs、MindSpore-docs 三个 docs 大站，`--skip=` 传空可覆盖；空值/缺失不参与判重，脚本同时输出"TDK 缺失检查"（逐页区分 元素缺失 / 元素存在但内容为空，孤立缺失也会报告），总览表含"缺失页 t/d/k"列，缺失与重复同为提 issue 触发条件
- 定时提 issue（`.github/workflows/tdk-duplicate-check.yml`，每周一 03:30 UTC + 手动 dispatch）：`--submit-issues` 模式下逐项目处理——
  - 扫描前先查该项目 AtomGit 仓库（owner/repo 由 `projects.config.json` 的 `repo` URL 解析）是否存在标题前缀 `[GEO TDK Duplicate]` 的未关闭 issue，存在则整个"扫描+提 issue"流程跳过该项目（不重复扫描、不重复提单）；查询失败且有 token 时同样跳过以防重复提单
  - 扫出重复时为每个项目生成简短/完全两份 md 报告：`scheduled-reports/tdk/<日期目录>/<ID>-brief.md` 与 `<ID>-full.md`（另有当日汇总 `report.md`）
  - 向该项目 AtomGit 仓库提 1 个 issue（标题前缀 `[GEO TDK Duplicate]`），正文用简短版报告，含提示文案与指向本仓库完全版报告的链接（`https://github.com/<GITHUB_REPOSITORY>/blob/<运行分支>/scheduled-reports/tdk/<日期目录>/<ID>-...-full.md`，随运行分支）
  - issue 关闭（修复后）下一轮才会重新扫描该项目；`--dry-run` 只打印不提单

## 人工检查要点

- title 是否遵循"页面内容 - 网站名称"模式
- description 是否概括页面内容而非关键字堆砌
