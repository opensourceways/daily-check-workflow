# 失效链接（死链）检测方式

> 本维度检测各门户站点源码仓中引用的链接（站内相对路径 + 外部 URL）的可达性。
> 移植自 linkcheck 分支（原作者 Python 版 scan_links.py 的 JS 移植），2026-10 接入 main 的例行检查流程。

## 检测项

| 检测项 | 检测方式 | 预期结果 | 自动化 |
|--------|----------|----------|--------|
| 源码链接提取 | clone 源码仓（repo 的 AtomGit 同名镜像，`linkScan.branch` 分支，浅克隆 depth=1）→ 扫描 `.js/.ts/.jsx/.tsx/.vue/.html/.css/.md/.txt` 文件，逐行提取 markdown 链接 / `href` / `src` / 裸 `https?://` URL（含中英文终止符清洗、HTML 实体剥离、未闭合括号处理） | 提取全部静态可解析 URL | ✅ 脚本 |
| 动态变量链接过滤 | 模板占位（`{{…}}`、`<%= %>`）、JS 属性链（`a.b.c`）、`$var`、`@alias` 特征匹配 | 跳过不探测（运行时拼接 URL 直探必误报） | ✅ 脚本 |
| 图片链接过滤 | 扩展名判定（png/jpg/svg/webp/ico 等） | 跳过不探测（源码图片资源普遍由构建/CDN 兜底，可达性噪声大） | ✅ 脚本 |
| API 目录过滤 | 文件路径含 `/api/` 的文件整文件跳过 | 跳过（接口 URL 多为运行时拼接） | ✅ 脚本 |
| 站内相对路径补全 | `/` 开头路径：静态资源直接拼 `domain`；其余先加 `linkScan.urlPrefix`（如 openEuler `/zh`）再拼 domain；已是 `/zh/` `/en/` 开头或协议相对（`//`）不再加前缀 | 转为可探测的绝对 URL | ✅ 脚本 |
| 链接可达性 | 唯一 URL 去重后并发探测：HEAD 优先（省流量），状态 ≥400（含不支持 HEAD 的 405/501）或 HEAD 网络失败时 GET 复核（取响应头即取消 body，不整页下载）；跟随重定向；超时/抖动/并发见 `check-rules.json` 的 `links` 段 | HTTP < 400 为有效；4xx/5xx/网络错误计失效 | ✅ 脚本 |
| 排除规则 | `linkScan.excludeDomains`（域名及子域）、`linkScan.excludeUrls`（精确或子串，用于运行时拼接的已知误报 URL）、`linkScan.excludeFiles`（相对路径子串；`.git/`、`node_modules/` 内置硬排除） | 命中排除规则的链接不探测 | ✅ 脚本 |

## 自动化检查

- 检查脚本：`scripts/checks/check-links.mjs`（支持 `--site=<id>` / `--conc=N` / `--max=N` 试跑截断，package.json 别名 `check:links`）；支撑库 `scripts/lib/link-scan.mjs`
- 执行方式：GitHub Action 定时（每周一 06:30 UTC）或 workflow_dispatch；本地 `node scripts/checks/check-links.mjs --site=openEuler-portal --max=50`
- 扫描范围：**仅 projects.config.json 中配置了 `linkScan` 的项目**（4 个 portal：openEuler-portal / openGauss-portal / MindSpore-portal / openUBMC-portal）；未配置的项目在报告中记 ➖ 不扫描、不查重、不提单
- 输出：
  - `scripts/stats/link-stats.json`：每项目含扫描文件数、链接引用数、探测 URL 数（去重后）、失效 URL 数、状态分布、逐失效 URL 的引用位置（file:line）
  - `scheduled-reports/links/YYYY-MM-DD/report.md`（汇总总览）+ `<ID>-brief.md`（简短版，issue 正文用）+ `<ID>-full.md`（完全版，全部失效 URL × 引用位置）
- 探测参数（改口径只改配置）：`scripts/config/check-rules.json` 的 `links` 段——`workers`（并发，默认 5）、`timeoutSeconds`（默认 15）、`delaySeconds`（每任务随机抖动上限，默认 0.5，缓解对同一目标站点的请求密度）

## 与相邻维度的边界

- **measures/09-internal-link（内链结构分析）**：09 分析站内链接的**结构**（有向图、孤岛页面、内链密度，一次性人工分析工具）；本维度检测链接的**可达性**（死链，例行自动检查）。两者互补，数据源同为源码仓
- **TDK/JSON-LD/语义化等线上维度**：数据源为 sitemap 展开的线上页面 HTML；本维度数据源为**源码仓文件**，可覆盖 sitemap 未收录的页面与构建产物之外的引用（如文档正文中的外链）
- 与 llms.txt 维度的"抽样链接可达"不重叠：llms 维度只抽 llms.txt 中前 3 条链接，本维度全量

## 提 issue 流程（--submit-issues）

- **提单账号**：与其他维度不同，本维度在 CI 中使用独立 secret `HSJ_ATOMGIT_TOKEN`（HSJ 账号令牌）提单/更新/评论 `/close`（其他维度仍用 `ATOMGIT_TOKEN`，即原提单账号）；正文尾部署名"由 daily-check-workflow 失效链接检查（check-links）自动生成"。脚本本身不感知账号差异——公共实现 `atomgit.mjs` 只读 `ATOMGIT_TOKEN` 环境变量，由 link-check.yml 做映射
- 脚本带 `--submit-issues` 运行时：逐项目先向 AtomGit 目标仓库查重（标题前缀 `[GEO Link Check]`，常量定义于 check-links.mjs，变更会使旧 issue 查重失效），存在未关闭同前缀 issue 则跳过该项目整个"扫描+提单"；查重与写回由 `scripts/lib/atomgit.mjs` 的 `precheckExistingIssues`/`reconcileIssue` 公共实现（各维度一致）
- **强制执行模式（`--force`，对应 workflow 手动输入的 `force_check`）**：复检仍有失效链接 → PATCH 就地更新原 issue 标题与正文（不新建）；失效链接已消除且本轮为有效扫描（clone 成功且探测了 ≥1 个 URL）→ 在原 issue 评论 `/close` 自动关闭；clone 失败时不下"已修复"结论、不评论
- 触发提单条件：**存在失效链接**（HTTP ≥400 或网络错误）；clone 失败（分支改名/仓库不可达等检查侧配置问题）只记报告与控制台，不提单
- 正文形态：**双报告**（简短版 = 状态分布 + 按状态分组每组前 5 个 URL；完全版 = 全部失效 URL 与全部引用位置），issue 正文用简短版 + 指向本仓库完全版的链接
- GitHub Action：`.github/workflows/link-check.yml`（每周一 06:30 UTC + workflow_dispatch 支持 `site`/`dry_run`/`force_check`），产物报告 commit 回本仓库 `scheduled-reports/links/<YYYY-MM-DD>/`

## 对 linkcheck 分支原实现的调整（移植决策记录）

1. **数据源 gitcode → AtomGit 镜像**：gitcode 对匿名 git 传输返回 401（login-gated，CI 无法匿名 clone），而各项目在 AtomGit 上有同名镜像（即本仓库提 issue 的目标仓库；openEuler master 实测与正源保持小时级同步）。公开仓匿名 clone，受限仓用 `ATOMGIT_TOKEN` 认证。原分支的 `issue_repo_platform: gitcode` 配置项实为死配置（issue 一直走 AtomGit API），移植时移除
2. **单 issue 模型**：原分支按 `issue_group_by`（all/status/file/domain）可对同一社区开多个 issue 且标题带日期（每周刷新一批、`/close` 关旧 issue）。为对齐 main 各维度共用的 `reconcileIssue`（稳定标题查重 + 就地更新 + 防误关护栏），改为**每项目至多一个 issue**，分组信息降级为报告正文内的状态分组展示；`issue_group_by`/`issue_status_codes` 配置项随之移除（状态码过滤口径会漏报 DNS 失效等真实死链，也不再保留）
3. **唯一 URL 去重探测**：原分支逐"引用处"探测，同一 URL 在多个文件出现会被重复探测。改为唯一 URL 去重后探测、结果映射回全部引用位置（报告仍逐处展示），大幅降低网络成本
4. **零依赖**：原分支依赖 `yaml` 解析独立配置文件；移植后配置并入 `projects.config.json`（`linkScan` 字段）+ `check-rules.json`（`links` 段），保持本仓库"零依赖、checkout 即跑"的 CI 形态
5. **中文标点截断改进**：原裸链接正则会把紧随 URL 的中文文本吞进 URL、再被中文保护逻辑整条判无效丢弃（"…链接 https://x.com/a，另见…"这类中文文档高频写法会漏检）。移植时把中文标点（，。；：！？）等）加入截断字符类——裸中文标点本就不可能合法出现在 URL 中，该改法只增检出不增误报
6. **clone 韧性**：浅克隆 `--depth=1`（原 `--depth=100` 无意义多拉历史）；AtomGit 大包传输偶发 `curl 18/56` 瞬时错误，内置匿名 3 次重试 + token 两种凭证格式重试；`GIT_TERMINAL_PROMPT=0` 防凭证提示挂死

## 人工检查要点

- **网络错误类失效需复核**：超时/DNS/TLS 失败可能来自目标站点临时故障或对探测 UA 的拦截（WAF/防爬），不代表链接真死。issue 正文已附复核说明；确认临时故障可评论说明后关闭
- **动态拼接 URL 的漏报与误报**：`item.url`、`/api/` 目录整文件跳过是保守取舍——站内由 JS 动态渲染的链接不在检测范围（已知盲区）
- **HEAD 不支持的站点**：探测以 GET 复核兜底，但个别站点对 HEAD/GET 行为不一致（如 HEAD 403 + GET 200），按最终 GET 结果判定
- **`urlPrefix` 口径**：相对路径加 `/zh` 前缀是"默认中文路由"的约定近似，个别项目可能存在 `/` 与 `/zh/` 双路由或相反映射，配置在 `linkScan.urlPrefix` 可逐项目调整
- 探测使用的浏览器 UA（`Mozilla/5.0 … Chrome/121`）刻意区别于仓库其余抓取的 `geo-workflow-checker/1.0`——部分外站 WAF 拦截非常规 UA 造成 403 误报
