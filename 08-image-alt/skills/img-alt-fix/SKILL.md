# 需要做什么

为图片补充描述性 alt（`*.md`、`*.vue`、`*.html`）：

- Markdown 图片：`![这里写 alt](./figures/xxx.png)`，方括号内容即 alt；
- HTML 标签：`<img>` 上补充 `alt` 属性；
- 以下模式均视为 alt 缺失，需逐一修复：

```markdown
![](./figures/RA-arch-1.png)                          ← 空 alt
![img](./figures/install-summary.png)                 ← 无意义占位
![image](./figures/topo.png)                          ← 无意义占位
![图1](./figures/deploy.png)                          ← 仅编号
![zh-cn_image_0000001372249333](./images/xxx.png)     ← 转换工具生成的文件名式占位
![xxx.png](./figures/xxx.png)                         ← 文件名回显
<img src="./figures/topo.png" width="500">            ← HTML 标签缺 alt 属性
```

- **仅补充 alt，不改动图片本身、图片路径及正文内容**（内容勘误等请另行提交 PR）；
- 中英文文档的 alt 分别使用各自语言撰写；

## alt 撰写规范

**基本原则：**

1. **描述图片传达的信息**，让不看图的人也能获取关键内容；避免以 `图片：`、`图：`、`截图：` 开头（alt 本身已隐含"这是一张图片"）；
2. **简洁**：中文一般不超过 30 字，复杂架构图可放宽至 50 字左右；
3. **结合上下文**：说明该图在当前操作步骤或论述中的作用，而非泛泛描述画面；
4. **不堆砌关键词**：alt 与页面主题自然相关即可，关键词堆砌会被搜索引擎判定为作弊。

> [alt内容及图片类型决策流程](./references/img-alt-decision-tree.md)

**分场景示例：**

| 图片类型 | 撰写要点 | alt 示例 |
| --- | --- | --- |
| 架构 / 拓扑图 | 概括主体组件及其关系 | `RAM-A 架构图：管理面通过 RPC 接口连接内核态模块与远端存储后端` |
| UI 操作截图 | 界面名称 + 关键区域或操作点 | `安装概览页面，"软件选择"选项处于高亮状态` |
| 命令 / 配置截图 | 说明展示的命令及目的 | `执行 rpm -qa 查询已安装软件包的输出结果` |
| 流程图 | 概括流程阶段 | `系统升级流程：检查更新、下载软件包、安装、重启` |
| 数据图表 | 说明指标与结论 | `各版本启动耗时对比：24.03 LTS 较 22.03 LTS 缩短约 30%` |
| 纯装饰性图片 | 保留空 alt（语义上正确，屏幕阅读器会跳过） | `![](./figures/spacer.png)` / `<img src="..." alt="">` |

> 技术文档中的图片绝大多数承载信息（架构、操作、结果），都应撰写描述性 alt；仅分隔线、背景装饰类图片保留空 alt。

## 示例

**Markdown 修改示例：**

```markdown
<!-- 修改前 -->
系统整体架构如下图所示。

![](./figures/RA-arch-1.png)

<!-- 修改后 -->
系统整体架构如下图所示。

![RAM-A 整体架构：管理面通过 RPC 接口连接内核态模块与远端存储后端](./figures/RA-arch-1.png)
```

**HTML / vue 标签修改示例：**

```html
<!-- 修改前 -->
<img src="./figures/topo.png" width="500">

<!-- 修改后 -->
<img src="./figures/topo.png" width="500" alt="集群组网拓扑：三个计算节点通过交换机与存储节点互联">
```

## 注意事项

1. alt 内容与图片下方的图注（如有）语义一致即可，不必逐字重复；图注渲染在 `<img>` 标签外部，搜索引擎与屏幕阅读器无法将其与图片关联，因此**不能**用图注替代 alt；
2. 命令输出类截图若正文已提供可复制的命令或代码块，alt 概括其展示目的即可，不必复述全部输出；
3. 历史图片若无法判断内容，结合上下文概括描述；
4. 修改时注意不要破坏 markdown 图片语法（方括号、圆括号需配对，图片路径保持不变）；
